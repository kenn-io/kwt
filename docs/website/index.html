kwt.sh

Give every task its own checkout.

kwt is a Git worktree manager with a terminal dashboard for people and a scriptable CLI for coding agents and other tools. It creates isolated checkouts, opens their tmux workspaces, shows their current state, and cleans them up safely, across all your projects.

Go go install go.kenn.io/kwt/cmd/kwt@latest
Then, in a repo kwt

One Go binary. Prebuilt macOS, Linux, and Windows archives with checksums ship on GitHub Releases. Workspaces need Git 2.20 and tmux 2.1 or newer. See all install options.

01 / Isolation

A checkout per task. A session per checkout.

Two agents on one checkout is a merge conflict with extra steps. kwt gives each branch its own worktree and its own tmux session, created together by one command, so parallel work never shares a working directory. The dashboard then shows all of them, across every repository you have registered, in one place.

  1. Command1kwt add -b feature/new-ui creates the branch, the checkout, and the workspace. --no-launch skips tmux.
  2. Shared checkouts0Each task gets its own directory and its own session. Nothing waits on a stash or a switch.
  3. ProjectsallRun kwt in any repository to register it. The dashboard lists every project's worktrees together.
  4. Binary1One Go binary. A local daemon auto-starts to own shared inventory and goes away when idle.
  5. State$KWT_HOMEConfig, the project registry, and pull-request records live together, so kwt's state isolates or backs up as a unit.

02 / Dashboard

Every project, every worktree, one screen.

The dashboard is where a person steers. Each row is a worktree with its branch, dirty and ahead/behind state, last activity, and whether its workspace is live. Create, attach, switch projects, and remove without leaving the keyboard. A plain directory can be a workspace too: run kwt in it and enter opens a tmux session in place.

Create

n for a new branch, b for an existing one.

n names a branch and creates its worktree and workspace. b searches local and remote branches and checks one out inert, ready for review.

Attach

enter opens the workspace.

Attach to the row's tmux session, creating it with the chosen layout when needed. c drops into a shell there instead; K kills a live session.

See

State you would otherwise go and check.

Changes as ~3 ?1, heads as ↑2 or local only, activity age, and workspace state, refreshed from the daemon's inventory across every project.

Move

Switch, filter, search, remove.

P changes the active project, p filters rows, / searches. d confirms the exact checkout before removing it; primary checkouts cannot be removed here.

03 / Automation

The same lifecycle as plain commands and stable JSON.

An agent does not need the dashboard. Every step a person takes there is a command with a documented result: create, resolve a path, run something inside, read back exactly what changed, remove. Results are bound to a worktree generation, so a snapshot of a checkout that was replaced mid-inspection is discarded instead of returned.

Inventory

A bare array, always current.

kwt list --json returns path, branch, commit, generation, repository slug, and the session endpoint for each worktree. It never prints cached data; it fails instead.

Changes

The exact changed files, once.

kwt changes --json separates staged from working-tree changes and includes untracked files, renames, deletions, and conflicts. Pass --expected-generation to bind it to the checkout you reviewed.

Errors

A machine-readable envelope.

Failures write { "error": { "code", "retryable", "details" } } to stdout and one human line to stderr. Codes and exit statuses are the contract; messages are prose.

Sessions

Establish a workspace for another client.

kwt open <path> --start-session --json creates the session without attaching and reports session_name, tmux_socket_name, and tmux_attach_mode for the terminal that will.

04 / Layouts

Workspaces that open with the agents already running.

A layout is a named set of tmux panes. Name your agent commands once, compose them into presets, and every new workspace starts with the right processes in the right panes. Layouts are opt-in: pick one with --layout, the L key, or layouts.default, or leave a workspace as one blank shell.

05 / Safety

Inert until you look.

A branch you did not write is untrusted data. When kwt checks out an existing or remote branch, or imports a pull request, it does not run repository hooks, setup commands, or file copies, and it does not start tmux or any agent. You review the checkout first. Only an explicit open starts the workspace.

Pull requests

Import behind a protected boundary.

kwt pr import creates an inert checkout that preserves the contributor branch's exact push destination. Attachment goes only through kwt pr attach; direct open and the dashboard refuse it.

Removal

Dirty work and live processes stop it.

kwt remove refuses a worktree with uncommitted changes or one that a running process has as its current directory, and lists the process IDs. --force is a decision you make after looking.

Trust

Repository config is gated.

A repository's .kwt.toml can choose layouts and setup, but only after you trust it. Branch names, refs, and pull-request metadata are never interpolated into shell commands.

Freshness

Stale guards fail closed.

Removal and inspection can be bound to the generation you displayed. If the workspace changed underneath you, kwt reports it and asks for a new decision instead of acting on old facts.

06 / Maintenance

Read-only by default. Previews before removal.

Worktrees accumulate. Repositories move. Directories get deleted outside kwt. The maintenance commands inspect without changing anything, show the complete decision set before removing, and repair only what they can prove has one safe answer.

Status

Branch, dirty, ahead, behind, activity.

kwt status summarizes every worktree across projects, including multi-machine state when sync is on. It is read-only.

Doctor

Diagnose, then repair only the obvious.

kwt doctor finds broken Git backlinks, stale metadata, and registry drift. --fix repairs findings with one provable answer, rescans, and leaves the rest for a person.

Prune

An explicit policy, previewed.

Bare kwt prune is a usage error. --expired or --merged with --dry-run shows every decision first. Merged pruning needs a confirmed merged pull request and keeps the local branch.

Outcomes

Named stops, not silent partial states.

doctor_required points you at inspection. cleanup_incomplete reports files left behind. Unattended merged pruning of a dirty checkout returns confirmation_required instead of guessing.

07 / Interfaces

One lifecycle across every surface.

A local daemon owns the shared inventory and serializes mutations. The dashboard, the CLI, Go applications, and terminal clients all work against the same registry and the same safety rules. Ghosthub embeds these services to manage worktrees and tmux workspaces across local and SSH-hosted machines; nothing in them is Ghosthub-specific.

  • Dashboardkwt or kwt tui: the cross-project, multi-machine view.
  • CLI + JSONStable arrays, error envelopes, and exit codes for agents and scripts.
  • Go packagego.kenn.io/kwt: inventory, removal, inspection, and SSH services in process.
  • Local daemonOne lifecycle owner per machine, with streamed operation events.
  • tmux endpointEstablish the right session, then hand it to your own terminal client.
  • SSH routesReviewed OpenSSH routes and leases for worktrees on other hosts.

08 / Sync

Know where a branch lives. On every machine.

Work happens on a laptop, a desktop, and a box in the closet. Multi-machine sync publishes each machine's worktree manifest to a hub you run, and the dashboard shows where a branch exists, whether machines saw different heads, and where dirty files were last seen. It is advisory: kwt never moves files or commits, clones anything, or deletes on another machine.

09 / Boundary

Not a git alias. Not an agent runner.

git worktree is plumbing: it makes a checkout and stops. Agent frameworks run models and stop. kwt is the layer between: it owns the lifecycle of the checkouts your agents work in, and it reads back what they did. Bring the agents you already use.

git worktree

The plumbing.

Creates and lists checkouts for one repository. No registry across projects, no sessions, no dirty or live-process guard, no inert imports, no JSON contract.

kwt

The lifecycle.

Registry, workspaces, layouts, inspection, guarded removal, pull-request import, maintenance, and multi-machine state, for people in the dashboard and agents on the CLI.

Your agents

The work.

Codex, Claude Code, review tools, whatever you run. kwt hands each one an isolated checkout with the right panes, and shows you what changed.
